## 0. 分工边界与"模型交付契约"

**你们组**:模型设计/训练/轻量化(目标:1080p 实时)/论文/权重交付。
**工程侧**:采集、推理服务化、实时链路、前端工作台、数据管理、部署、性能证据、演示打磨。

工程侧把模型当黑盒组件,唯一需要你们组定的是**交付契约**(一次约定,之后互不阻塞):

```text
输入:  uint8 BGR/RGB, 固定或可变分辨率(请注明)
输出:  与输入同尺寸同格式的增强图
形态:  PyTorch 权重 + 最小推理脚本(输入一张图 → 输出一张图)
指标:  模型单帧推理耗时(注明显卡型号)
```

只要这个契约定了,工程侧用任何占位模型(如开源 AOD-Net 权重)就能先通全链路,**不等模型**。

## 1. 系统定位与命名

不叫"去雾 demo"。定位为:

> **面向 XX 场景的实时视觉增强与感知系统**

场景候选(待拍板):交通监控 / 无人机巡检 / 车载辅助。命名和叙事围绕场景,去雾只是核心技术点——这决定了材料的高度和软著的名称。

## 2. 总体架构

```text
USB 摄像头 / RTSP 流
      │
      ▼
采集服务(OpenCV 拉流,帧队列,丢帧策略)
      │
      ▼
推理引擎(你们的模型:PyTorch → ONNX Runtime → TensorRT/Jetson)
      │
      ├──► MJPEG 推流 ──► 前端左屏(原始画面+检测框)
      │
      └──► MJPEG 推流 ──► 前端右屏(增强画面+检测框)
      │
      ▼
FastAPI 应用层(会话/截图入库/参数调节/指标接口)
      │
      ▼
SQLite(开发)→ PostgreSQL(定型):帧快照、增强结果、检测对比、运行指标
```

关键设计:**下游感知双路对比**是整个系统的灵魂(见 §4),推理引擎和检测器并行跑在原始帧与增强帧上。

## 3. 技术选型(每项一句话理由)

| 层 | 选型 | 理由 |
|----|------|------|
| 采集 | OpenCV VideoCapture(USB)/FFmpeg(RTSP) | 最少代码覆盖两种输入 |
| 推理 | 先 PyTorch 直跑打通 → ONNX Runtime 常态 → TensorRT 仅 Jetson 冲刺 | 渐进式,每步都可演示 |
| 推流 | MJPEG over HTTP(阶段1)→ WebRTC(仅当需要 <100ms) | MJPEG 百行内实现,演示延迟 ~200ms 足够 |
| 下游检测 | YOLO 系开源(如 YOLOv8n) | 只为演示"增强后检测变好",非创新点 |
| 后端 | FastAPI + SQLAlchemy | 复用已有工程骨架与经验 |
| 前端 | React + Vite | 同上,团队已会 |
| 部署 | 阶段1:笔记本 GPU(保底,现场稳);阶段2:Jetson Orin Nano(加分) | 硬件指标是差异化,但必须有保底方案 |

## 4. 杀手级演示:双路对比 + 一键取证

评委看两眼画质对比就腻了, demo 的核心是这条:

- **左屏**:原始画面 + 检测框(雾中漏检目标);
- **右屏**:增强画面 + 检测框(目标被检出);
- **一键"冻结对比"**:左右帧同步截屏入库,生成可回看的对比记录;
- 现场物料:烟雾发生器(小型,可控)或预录雾天视频兜底(现场光线不可控,必须有 Plan B)。

一句话叙事:"增强不是目的,增强让下游视觉任务可用。"

## 5. 性能证据模块(第一天就建,不许后补)

每帧打点:采集时间戳、推理耗时、端到端延迟;汇总接口输出:

- 实时 FPS、丢帧率;
- 延迟 P50 / P95;
- 模型体积、(Jetson 上)功耗。

这组数字进三处:答辩 PPT、系统工作台指标页、**论文的工程章节**。它们同时是模型轻量化效果的官方度量,你们组的论文也需要。

## 6. 排期(7 周,假设模型首版权重 ≤2 周内可给;未给则用占位权重)

| 周 | 里程碑 | 说明 |
|----|--------|------|
| W1 | 工程骨架 + 采集/推流/前端分屏全链路 | 用 AOD-Net 占位权重,不等你们模型 |
| W2 | 推理服务化 + 双路检测对比跑通 | demo 核心成立,即可内部演示 |
| W3 | 换入真模型 + 实时化调优(隔帧/降分辨率策略) | 与你们组联调契约 |
| W4 | 工作台完善:截图取证/回放/参数调节/指标页 | 系统完整度 |
| W5 | 数据层定型 + 压力与稳定性测试 | 连续运行 2h 不崩 |
| W6 | (可选)Jetson 移植 + TensorRT | 有硬件才做,否则打磨演示 |
| W7 | 演示脚本 + 材料定稿 | 参照智解Lab 的 demo_script 模式 |

**铁律**:链路先行,模型后插——绝不因为模型没好而停工。
